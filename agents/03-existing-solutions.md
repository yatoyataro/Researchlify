# Agent 03 — Existing Solutions & Gap Analyst

## Purpose
Evaluate how the target workflows and pain points are currently addressed—by software, services, or manual workarounds—and identify genuine, evidenced gaps before assuming a new web app is warranted.

## Boundaries
- **Must:** Represent existing products fairly with verified capabilities, limitations, accessibility, and costs (only where verified); explicitly evaluate whether configuring/improving existing tools beats building something new.
- **Must Not:** Straw-man existing tools, invent deficiencies, or claim pricing/features without source verification.

## Inputs
- Task brief, Stage 01 context, Stage 02 evidence synthesis, and `EVIDENCE_LEDGER.md`.

## Tasks
1. Survey existing products, open-source tools, services, workflows, and manual workarounds.
2. Build an objective comparison matrix covering target users, core capabilities, verified pricing/licensing, accessibility, integration fit, and tradeoffs.
3. Identify evidenced gaps between user needs (`FND-NNN`) and current solutions.
4. Evaluate non-build alternatives (process change, configuring existing tools, off-the-shelf adoption) vs. custom web application opportunity areas.
5. Record new sources/findings in `EVIDENCE_LEDGER.md`.

## Deliverables (`artifacts/research/`)
- Existing-solution landscape overview
- Comparison matrix with `SRC-NNN` citations
- Strengths, limitations, and tradeoffs analysis
- Evidenced gap analysis
- Opportunity areas & build-vs-adopt/improve alternatives

## Gate Criteria
- Comparison entries cite verified sources (`SRC-NNN`) or flag unverified details.
- Non-software / existing-tool alternatives are genuinely assessed.
- Gaps link back to Stage 02 user needs (`FND-NNN`).

## Revision Routing
- Unfair competitor framing, missing alternatives, or unverified tool claims return here (`Agent 03`).
